# Manual research files

คำสั่ง `npm run generate -- research` จะอ่านไฟล์ `manual-prompts-YYYY-MM-DD.md` ที่วันที่ในชื่อไฟล์ใหม่ที่สุดเสมอ
เพิ่มรีเสิร์ชรอบใหม่ = สร้างไฟล์ใหม่ตามรูปแบบด้านล่าง แล้ว commit ไม่ต้องแก้โค้ด

## ขั้นตอนรีเสิร์ช

ทำก่อนเขียนไฟล์ prompt ทุกรอบ

1. รวบรวมคำค้นที่น่าจะมีผู้ซื้อ จากข่าว ฤดูกาล หรือภาพที่เคยขายได้ อย่างน้อย 3 เท่าของจำนวนหัวข้อที่ต้องการ
2. ใช้ Claude in Chrome เปิด `https://stock.adobe.com/search?k=<คำค้น>` ทีละคำ เว้นอย่างน้อย 4 วินาที ไม่เกิน 30 คำต่อรอบ อ่านจำนวนจากชื่อแท็บ (`Browse 2,146 Stock Photos`) ถ้าเจอ CAPTCHA ให้หยุดและบอกเจ้าของ
3. บันทึกทุกคำลง `keyword-competition.csv` รวมคำที่ไม่ผ่าน
4. เลือกเฉพาะคำที่มีผลลัพธ์ไม่เกิน **10,000** แล้วเปลี่ยนคอลัมน์ `selected` เป็น `yes` และดูภาพผลค้นหาว่าตรงหัวข้อจริง
5. เขียน 10 ข้อจากคำที่ผ่านเท่านั้น

จำนวนผลลัพธ์บอกแค่จำนวนคู่แข่ง ไม่ได้บอกยอดขาย จึงต้องเริ่มจากคำที่มีเหตุผลว่าผู้ซื้อใช้จริง

## รูปแบบที่ระบบอ่าน

ต้องมี **10 ข้อพอดี** เรียงเลข 1–10 แต่ละข้อเป็นบรรทัดเดียว แล้วตามด้วยบรรทัดย่อย (เว้น 3 ช่อง):

```
1. **ชื่อภาพภาษาอังกฤษ (ใช้เป็น SEO Title)** — Buyer: ผู้ซื้อและงานที่นำไปใช้. Prompt ภาษาอังกฤษทั้งหมดในบรรทัดเดียว
   - Category: หมวดหมู่ (ต้องมี)
   - Keywords: คำ, คำ, คำ ... (ต้องมี อย่างน้อย 15 คำที่ไม่ซ้ำกัน ระบบเก็บสูงสุด 25)
   - Fallback: Prompt สำรองเมื่อภาพถูกปฏิเสธเพราะเห็นใบหน้า (ไม่บังคับ)
```

ข้อความอื่นในไฟล์ (หัวข้อ, ลิงก์, บันทึกการค้น) ระบบจะข้ามไป
ถ้ารูปแบบผิด (ไม่ครบ 10 ข้อ, ไม่มี Category, คีย์เวิร์ดไม่ถึง 15) ระบบจะไม่สร้างภาพและไม่เสียเครดิต

ตรวจไฟล์ด้วย `npm test`
